# 供給網リスク（typosquatting・メンテナンス状況）の確認

CVE は「既知の脆弱性」を捕捉するが、悪意あるパッケージや放棄パッケージは CVE が出る前に被害を出す。
依存追加時に以下を軽く確認し、怪しければユーザーに注意喚起する。

## 1. Typosquatting（誤記便乗）

著名パッケージに 1〜2 文字違いで似せた悪意あるパッケージに注意する。

確認観点:

- 名前が著名パッケージの誤記に見えないか（例: `lodahs` vs `lodash`、`reqeusts` vs `requests`）
- スコープ付きパッケージ（`@org/pkg`）の `@org` が正規の発行元か
- ハイフン/アンダースコア/複数形の差し替え（`python-dateutil` 系の偽装）

```bash
# npm: 発行者・週間ダウンロード数・最終公開日を確認
npm view <pkg> maintainers time.modified
# PyPI: プロジェクトページで作者・リリース履歴を確認
#   https://pypi.org/project/<pkg>/
```

## 2. メンテナンス状況

- **ダウンロード数が極端に少ない**（週数十未満）→ 正規の人気パッケージの偽装か、未成熟。
- **最近作られたばかり**（公開から数日〜数週）→ 供給網攻撃の新規パッケージの可能性。
- **長期間更新なし**（数年放置）→ 脆弱性が放置されるリスク。

## 3. 判断

- 上記に該当する兆候があれば、インストール前にユーザーへ「このパッケージは○○の理由で要注意」と提示する。
- 正規パッケージであることが確認できない限り、導入を保留する。
- 見送り判断をしたら同ターンで `doc/backlog.md` に記録する（structure.md §6.1）。

## 4. 参考

- このチェックは CVE 照会（`check_package.py`）と**併用**する。CVE なし = 安全とは限らない。
- 既存 CI の Dependabot / Snyk も供給網シグナルを出すため、CI 結果も併せて確認する。
