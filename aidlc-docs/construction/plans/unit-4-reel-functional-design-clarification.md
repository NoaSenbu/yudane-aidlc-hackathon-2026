## 背景（Q1 回答の解釈）

Q1 回答: 「**MVP の段階では過去に購入したものをもとに関連製品を推薦するようにしたい**」

これは推薦エンジン（B-03 ReelRecommendationService）の **候補生成段** の方針を、推奨 A の「嗜好ベクトル近傍検索」から「**購入履歴ベースの関連商品**」へ具体化する指示と理解しました。一方で Q2（深夜ブースト）/ Q3（ストレス係数）/ Q10（カレンダー一致ブースト）は A で確定しており、これらは **順位（リランク）にブーストを効かせる** 前提です。

そこで、Q1 の MVP 方針と Q2/Q3/Q10 のブーストをどう両立させるか、また購入履歴が乏しい状況をどう扱うかを確定します。MVP（予選 5/30）と決勝（6/26）でスコープを分ける前提です。

## Clarification 1: MVP の候補生成（関連商品）の取得方式

「過去の購入をもとにした関連商品」を MVP でどう取得しますか？（ハッカソン段階は Creators API 未承認のため B-11 はダミーカタログ代替 = Q7 確定済み）

A) **カテゴリ/ブランド一致 + 共購買ヒューリスティック**: 直近購入の **カテゴリ・ブランド** に一致する商品を候補化し、ダミーカタログ（決勝後は Creators API の関連商品）から「よく一緒に買われる」型の関連商品を加える。Titan Embeddings + OpenSearch ベクトル検索は **MVP では使わず決勝で導入**（backlog 化）— 推奨（OpenSearch 依存を MVP から外せて軽量・テスト容易）
B) **Titan Embeddings + OpenSearch ベクトル近傍検索を MVP から採用**: 購入履歴を埋め込みクエリにして近傍商品を候補化（components.md の B-03 当初設計どおり。MVP の実装/インフラ負荷は増える）
C) **固定ダミーカタログからカテゴリ一致で返すだけ**（関連度ロジックは最小、決勝で本格化）

## Clarification 2: MVP でのリランク（ブースト）適用範囲

Q2/Q3/Q10 で確定した「深夜ブースト / ストレス係数 / カレンダー一致」のリランクを、Clarification 1 の候補集合の上に **MVP から適用** しますか？

A) **適用する（候補生成 = 購入履歴ベース関連商品 → その上に決定論的リランク）**: 時刻ブースト・ストレス係数・カレンダー一致・直近表示の減衰を重み付き加算スコアで順位化（純関数・PBT 可）。Q1 の MVP 方針と Q2/Q3/Q10=A を両立 — 推奨
B) **MVP では順位は購入履歴の関連度のみ**。深夜ブースト等は **順位ではなくコピー/タグの演出にのみ反映**し、リランクは決勝で導入（実装最小だが US-02-01 の「深夜に高単価が先頭」が順位として効かない）

## Clarification 3: 購入履歴が乏しい新規ユーザー（cold start）の扱い

購入履歴がまだ無い/少ないユーザーへのフォールバックをどうしますか？

A) **オンボーディング嗜好 + キュレーション固定リスト**: US-AUTH-01 で取得した「好きなブランド・カテゴリ」を初期シードにし、不足分は人気/キュレーションの固定リストで補う — 推奨（初回からフィードが成立）
B) **全ユーザー共通の人気カタログのみ**（オンボ嗜好は使わず、購入が貯まるまで汎用人気を表示）
