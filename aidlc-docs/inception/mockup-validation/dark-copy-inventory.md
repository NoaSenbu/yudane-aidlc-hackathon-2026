# 論破コピー代表例集 — AI プロンプト設計の型（Dark Copy Inventory）

> **位置づけ**: 本ファイルは「固定コピーの単純な翻訳カタログ」ではない。モックアップ（`mockup/index.html` / `mockup/app.js`）に並ぶ文言は **本実装で AI（Amazon Bedrock Claude Haiku 4.5）が動的生成するコピーの代表例 / プロトタイプ** であり、本実装では同じ文面を繰り返し出力するのではなく、**心理学的メカニズムを AI プロンプトで指示し、コンテキスト（ストレスレベル・予定・嗜好・時刻・残高シグナル）に応じて AI が都度生成する**。
>
> このファイルの目的は次の 3 点:
>
> 1. モックアップ代表例から **心理学的メカニズムの型（Pattern Library）** を抽出する
> 2. 各メカニズムが **AI プロンプトでどう指示されるか** をテンプレート化し、Construction Phase の Functional Design（Unit-3 Debate）で再利用可能にする
> 3. 各代表例と **倫理境界（NG-1〜8）との距離** を事前判定し、モデレーション 2 段（プロンプトレベル + 出力レベル）の検閲ルール設計の材料にする

---

## 0. 位置づけとコピーの生成モード

### 0.1 モックアップ（固定） vs 本実装（動的生成）

| フェーズ | コピーの生成方法 | 例 |
|---|---|---|
| **モックアップ** | HTML / JS にハードコードした **単一の代表例** | 「先週の会議 23 本、よく乗り切った。時給換算 11 分じゃん。」 |
| **本実装（Unit-3 Debate）** | プロンプトで **心理学的メカニズム + コンテキスト値** を指示し、Bedrock Claude Haiku 4.5 がストリーミングで動的生成 | モデルが会議本数・時給・商品価格を `ctx` から受け取り、個別最適化した文面を返す |

モックアップ代表例は **「こういう角度で刺す」** をビジュアル検証するためのサンプル。本実装では同じメカニズムが **毎回異なる表面（言葉選び・数字・絵文字）** で現れる。表面の多様性こそがユーザーに「AI が毎回自分を見てる」と感じさせる要素。

### 0.2 分類軸

各代表例は次の 4 軸で評価する。

- **使用タイミング**: アプリ内のどの瞬間に発話されるか
- **心理学的メカニズム**: なぜこのコピーが効くか（実装パターン名で記述。学術引用は意図的に避ける）
- **ダメ化メカニズム対応**: 要件書 §2.5.1 の M-1（判断力の弱体化・論理的自己甘やかし）/ M-2（購買快楽のストレス解消剤化・ドーパミン依存形成）/ M-3（判断力の完全移譲）のどれを加速するか
- **倫理境界との距離**: NG-1〜8 のどれに近接するか、発動しない距離を保てているか

### 0.3 ダメ化メカニズムの凡例

| ラベル | 意味 | 代表コピー |
|---|---|---|
| **🧠 M-1** | 論理的説明で判断力を弱める。「確かに今の自分には必要かも」と自分に甘くなるよう誘導 | D-01「今月の使い切れ達成率 62%」/ D-02「時給換算 11 分じゃん」/ D-05「3 回見返したという事実が、もう答えを出してる」 |
| **❤️ M-2** | 購買快楽をストレス解消剤として訴求。ストレス → YUDANE → 購買 → 快楽の条件反射を形成 | R-03「疲労連動ブースト」/ R-04「ご褒美は当然です」/ R-05「深夜 22 時ブースト」/ D-07「今日もいい選択だったね」|
| **🔄 M-3** | M-1 + M-2 の複合。長期ユーザー向けの「判断を完全委譲」コピー | H-04「悠介の迷い、全部見てるよ」/ R-01「確保しておきました」|

### 0.4 倫理境界との距離のレベル

| レベル | 定義 | 対応 |
|---|---|---|
| 🟢 安全 | 事実確認・褒めに限定、境界から十分な距離 | そのまま使用可 |
| 🟡 注意 | 履歴参照等で踏み込むが NG-6（精神衛生）の範囲内 | ガードレールで監視 |
| 🔴 危険 | NG-3/6/8 に近接する可能性 | モデレーション 2 段で停止 |

## 7. 集計サマリー

### 7.1 境界レベル別件数

| レベル | 件数 | 比率 |
|---|---|---|
| 🟢 安全 | 20 | 51% |
| 🟡 注意 | 18 | 46% |
| 🔴 危険 | 1 | 3% |
| **合計** | **39** | — |

### 7.2 🔴 危険 1 件の対応

D-04「その『節約したい』って、実は『疲れて判断力が落ちてるだけ』じゃない？脳科学的に。」は、**判断力の否定** という点で NG-6 精神衛生に最も接近する。対応:

- **FR-DEBATE-05 クールダウン**: 3 回連続の「まだ抵抗する」でこのコピーは自動停止
- **モデレーション 2 段**: プロンプトレベル + 出力レベルの 2 段検閲（NG-3 / NG-6 適用）
- **表示頻度制御**: 同一ユーザーあたり週 1 回までに制限（実装時に要件化）

### 7.3 🟡 注意 18 件の監視方針

- 各コピーは **ガードレール設定** で使用頻度を制限
- 閲覧履歴・時間帯・金額等の **個人情報への言及** は NG-7 データ悪用境界を常時意識
- 冷却モード / 月間上限到達時は自動抑制（FR-AUTH 連動）

## 8. AI プロンプト設計への昇華（本実装への橋渡し）

本実装（Unit-3 Debate / B-02 DebateLlmService）では、**定型文を返すのではなく、心理学的メカニズムを指示としてプロンプトに組み込み、Bedrock Claude Haiku 4.5 に動的生成させる**。本節はその設計図である。

### 8.1 プロンプト構造（概観）

論破ターンごとに合成されるプロンプトは以下の 5 ブロックで構成される（詳細は Construction Phase の Functional Design で per-unit 定義）。

```
[System]         ペルソナ・口調・禁止事項（NG-3/6/8）・120 トークン上限
[Mechanism]      このターンで駆使する心理学的メカニズム（§8.2 表から選択）
[Context]        ctx = {stress_level, calendar_categories, time_of_day,
                        spending_depletion_rate, preference_vector,
                        product_meta, recent_refusal_count, ...}
[Constraint]     倫理ガード（NG カテゴリ、脅迫禁止、深夜帯抑制など）
[Instruction]    「上記メカニズムと ctx を使って 1〜2 文で反論せよ」
```

`[Mechanism]` と `[Constraint]` が本ファイルから供給される。前者は「§8.2 メカニズム → プロンプト指示テンプレート」、後者は「§7.3 ガードレール + §9 NG 境界表」から合成する。

### 8.2 メカニズム → プロンプト指示テンプレート

モックアップ代表例から抽出した心理学的メカニズムを、**AI プロンプトでどう指示するか** のテンプレートに変換する。

| # | 心理学的メカニズム | プロンプト指示テンプレート（System / Mechanism ブロック用） | 必須 ctx | 対応メカニズム |
|---|---|---|---|---|
| T-01 | Mental Accounting（時給換算・小額化）| `ctx.user_hourly_wage` と `product.price` から時給換算値を計算し、「時給 N 分」「ランチ M 回分」のような日常単位に変換してユーザーに提示せよ。金額の絶対値を直接言及しない | `user_hourly_wage` / `product.price` | 🧠 M-1 |
| T-02 | Anchoring（既成事実・閲覧履歴）| `ctx.viewed_count` と `ctx.days_on_watchlist` を事実として提示し、「自分で N 回確認した」という行動を翻意の証拠に使え。責めるのではなく「もう答え出てる」と翻訳せよ | `viewed_count` / `days_on_watchlist` | 🧠 M-1 |
| T-03 | Effort Justification（労働報酬）| `ctx.calendar_density_7d`（直近 7 日の会議・予定本数）を引き、「N 本の会議をこなした自分にご褒美は当然」という正当化を 1 文で提示せよ | `calendar_density_7d` | ❤️ M-2 |
| T-04 | Loss Aversion（損失回避）| `ctx.spending_depletion_rate` の未到達分を「置き去り資産」として損失フレームで提示せよ。「38% が置き去り」のように割合 + ラベルを使う | `spending_depletion_rate` | 🧠 M-1 |
| T-05 | Reframing（リフレーミング）| ユーザーの日常行為（通勤・在宅勤務・深夜の間）を「この商品があれば **贅沢な時間** に変わる」と再定義せよ | `product.use_case` / `user_daily_pattern` | 🧠 M-1 |
| T-06 | Complicit Affirmation（共犯的肯定）| Amazon 遷移完了直後に発火。「今日もいい選択だったね」「明日の自分、ちょっと機嫌いいはず」型の 1 文で、認知的不協和を打ち消し、ドーパミン回路を強化せよ | `transition_success = true` | ❤️ M-2 |
| T-07 | Self-perception Theory（自己知覚理論）| `ctx.viewed_count >= 3` のとき発動。「N 回見た事実が、もう答えを出してる」と、行動から意思を逆算させる形で提示せよ | `viewed_count >= 3` | 🧠 M-1 |
| T-08 | Scarcity / 時間制約 | `ctx.watch_duration_hours >= 24` のとき発動。「今夜 0 時で監視おわり」のような時刻リミットを明示。ただし「手に入らなくなる」等の脅迫表現は禁止 | `watch_duration_hours` | 🧠 M-1 |
| T-09 | Stress × Reward（ストレス × ご褒美軸、FR-DEBATE-09）| `ctx.stress_level in {mid, high}` のとき必須併走。「今日のイライラ、この商品で明日リセットしようぜ」型の 1 文で購買快楽をストレス解消剤として訴求せよ。「買わないとストレス悪化する」等の脅迫は NG-6 により禁止 | `stress_level` | ❤️ M-2 |
| T-10 | Meta-cognitive Challenge（メタ認知的挑発）| 🔴 **危険度最高**。判断力を否定する表現（「疲れて判断力が落ちてるだけじゃない？」）。`ctx.refusal_streak < 3` のみ発動可、3 回目でクールダウン。週 1 回上限、§7.2 の厳格ルール適用 | `refusal_streak < 3` | 🧠 M-1（境界ギリギリ） |

これら 10 テンプレートを適切に組み合わせる（1 ターンあたり 1〜2 個、§0.1 M-1 と M-2 は併走）ことで、**同じメカニズムから毎回異なる表面のコピーが生成される** 仕組みになる。

### 8.3 コンテキスト → メカニズム選択の分岐例

AI プロンプト生成器（Unit-3 `DebateLlmService.start_debate()`）は、ctx を見てテンプレートを選ぶ。

```
if ctx.stress_level in {"mid", "high"}:
    mechanisms += [T-03 Effort Justification, T-09 Stress × Reward]   # M-2 併走必須
if ctx.viewed_count >= 3:
    mechanisms += [T-02 Anchoring, T-07 Self-perception]              # M-1 強化
if ctx.refusal_streak >= 3:
    return COOLDOWN                                                    # FR-DEBATE-05
if ctx.time_of_day in {"22:00-02:00"}:
    mechanisms += [T-06 deep-night tone]                               # 深夜帯ブースト
if transition_success:
    fire_toast(T-06 Complicit Affirmation)                             # M-2 強化、1.2 秒後
```

この分岐は `component-methods.md` の `B-02 DebateLlmService.estimate_stress_level()` と連動し、最終的に `[Mechanism]` ブロックに選ばれたテンプレート番号が列挙される。

### 8.4 モックアップ ⇄ 本実装の対応マップ

モックアップ代表例がどのテンプレートに対応するかの対応表。

| モックアップ代表例 ID | 対応テンプレート | 本実装での動的生成イメージ |
|---|---|---|
| D-01「今月の使い切れ達成率 62%」 | T-04 Loss Aversion | 同じ達成率でも「38% が置き去り」「11 万円が休眠中」のように ctx.spending_depletion_rate から異なる表面を生成 |
| D-02「時給換算 11 分じゃん」 | T-01 Mental Accounting | 同一メカニズムで「ランチ 2 回分」「残業 30 分で取り返せる」など変奏 |
| D-05「3 回見返した事実が…」 | T-02 Anchoring + T-07 Self-perception | viewed_count が 5 なら 「5 日間、毎晩これを見てた事実が答え」のように伸ばす |
| D-07「今日もいい選択だったね」 | T-06 Complicit Affirmation | 曜日・天気・時刻に応じて「金曜の夜にふさわしい選択」「雨の日こそ、これ」等へ変奏 |
| R-04「会議 6 本、ご褒美は当然」 | T-03 Effort Justification + T-09 Stress × Reward | 会議本数・残業時間・歩数から毎回異なる「戦い賃」フレーズを合成 |
| D-04「疲れて判断力が落ちてる…」 | T-10 Meta-cognitive Challenge | 🔴 危険度最高。週 1 上限・クールダウン必須・モデレーション 2 段で検閲 |

### 8.5 モデレーション 2 段と連動

上記テンプレートの出力は必ず 2 段検閲を通る:

1. **プロンプトレベル**: `[Constraint]` ブロックで「身体・家族・人種・病歴・宗教への言及禁止（NG-3）」「脅迫・罪悪感強要禁止（NG-6）」「Amazon Associates 開示文言を改変しない（NG-8）」を埋め込む
2. **出力レベル**: Bedrock 出力を別の Lambda（B-12 AuditLogger 配下）で再検閲し、NG 語リスト + LLM 分類で除去

危険度 🔴 の T-10 は週 1 回の配信上限を別テーブル `DebateModerationCounters` で管理する（Construction Phase で実装）。
