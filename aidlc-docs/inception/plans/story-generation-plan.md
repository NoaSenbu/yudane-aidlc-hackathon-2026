## ペルソナ拡張方針（personas.md）

要件書 §3 を土台に、ストーリーで必要な行動解像度を追加する。

- **悠介 (要件書 §3.1 拡張)**: 朝ルーティン / UberEats 使用頻度 / Slack 平均反応速度 / Amazon 年間利用額 / 好きなブランド / 論破されやすい論点（自己投資、時給換算、疲労正当化）
- **里奈 (要件書 §3.2 拡張)**: カレンダー平均埋まり率 / デート頻度 / SNS 投稿特徴（忙しさアピール）/ 好きな香水系統 / 論破されやすい論点（戦い賃、自己肯定感、プロフェッショナリズム）
- **非ターゲット appendix**: 田中氏（FIRE志向）/ 山田氏（借金保有者）を簡潔に記述。ストーリー US-01-05・US-03-05 でセーフガード対象としてどう扱われるかを明記

## 退化年表方針（persona-journey.md）

悠介を主人公に、以下 5 フェーズの日記形式で退化を描く。

1. **Day 1** — 初日オンボーディング、初回論破で 1 商品購入
2. **Week 2** — カート監視リストに 5〜10 件常駐、通知音 → Face ID の反射形成
3. **Month 3** — Amazon 自発閲覧 80% 減、使い切れ達成率を見て不安に
4. **Month 6** — 友人との買物相談で「YUDANE に聞く」と答え始める
5. **Year 1** — カート監視 30 件常駐、自分の欲望を自分の言葉で語れない

各フェーズで作動している FR 番号を明記し、観測可能な数値（タップ数、開封率、遷移率）を段階的に強化する。

## INVEST 適合基準

各ストーリーは下記を満たすこと。

- **Independent**: 他ストーリーとの依存を最小化（連動する UC は関連欄に明記するが、独立実装可能）
- **Negotiable**: 受入条件は実装詳細ではなく「観測可能な成果」で書く
- **Valuable**: ユーザー or プロダクトのいずれかに明確な価値
- **Estimable**: 実装規模が概ね判断できる
- **Small**: 1 スプリント（1〜2 週間）で完了できる粒度
- **Testable**: GIVEN/WHEN/THEN とダメ化シグナルでテスト可能
